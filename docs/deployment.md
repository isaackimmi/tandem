# Vercel deployment preparation

**Prepared for review; not deployed. Do not merge this optional PR automatically.**

Tandem uses one monorepo and one Vercel project with two Services: Next.js and FastAPI. Services is currently beta. Local development continues to use the existing one-command runner. The Python model, CSV, thresholds, and API contract are unchanged.

## Routing and packaging

`vercel.json` sends `/api/*`, `/health`, and `/ready` to the backend; all other paths go to Next.js. Vercel preserves the full incoming path. The frontend's `API_ORIGIN` service binding reaches the backend in the **same deployment**, including previews. The existing runtime `connection()` boundary prevents server catalog requests at build time.

Browser requests use relative `/api/v1/...` URLs. The frontend service build explicitly sets `NEXT_PUBLIC_API_ORIGIN` to an empty string; it does not bake a localhost address, a production hostname, or the private binding into browser JavaScript. The server binding is supplied by Vercel at runtime; do not set it manually. Same-origin browser requests do not require a preview-domain CORS allowlist or wildcard.

The frontend service root is `client/`. The backend root is the **repository root**, so `references/CMPE256_Hackathon_market_basket_analysis_Release.csv` remains inside its build boundary. `vercel_backend.py` exposes the existing application with the same import path as the local runner; it does not copy the CSV or mine rules itself. Python 3.12 and pinned runtime dependencies are declared at the root. Development-only pytest/httpx dependencies remain in `server/requirements.txt`; runtime pins have one source in the root `requirements.txt`; the local runtime manifest includes it. The hosted builder failed to resolve an included nested requirements file, so its root manifest is deliberately self-contained.

The backend function excludes frontend files, documentation, test assets, and local environments. Do not exclude `references/`, `server/app/`, or `server/tandem/`. No database, upload bucket, writeable persistent filesystem, or external model is required.

Keep provider build/install overrides unset; each service owns its configuration. The frontend install command explicitly runs npm 11.6.2 so it matches the lockfile and CI instead of relying on Vercel’s default npm. Use Node.js 22.x and Python 3.12.
2. Ensure the project can use Services beta. Do not add `experimentalServices` or configure an independent frontend project on top of this file.
3. Set the environment values below for both Preview and Production. Do not upload local `.env` files or set manually generated preview hostnames.
4. Create a preview only after Isaac authorizes deployment. Inspect both service build logs and function bundle contents/size, then perform the acceptance checks below before promoting it.
5. Promote the exact accepted deployment. Record its deployment ID, Git SHA, modelVersion, thresholds, test evidence, and date. A deployment is the versioned unit for both services.

| Variable | Value / owner |
| --- | --- |
| `API_ORIGIN` | Generated by the `web → backend` runtime service binding. No manual value. |
| `NEXT_PUBLIC_API_ORIGIN` | Forced empty by the frontend build command for relative browser requests. |
| `MIN_SUPPORT` | `0.005` (also the code default). |

Vercel owns hosted function startup; do not run the local root `npm start` or Uvicorn command as the deployment build. No credentials belong in a `NEXT_PUBLIC_` variable.

## Hosted acceptance still required

This PR cannot prove hosted behavior without creating a deployment. Record these results on the PR after an authorized preview:

- `/health` returns 200 and `/ready` reports 40 products, 15 rules, a stable modelVersion and startupSeconds. Inspect a newly initialized instance and repeated warm requests. Lifespan must execute before requests; mining runs once per initialized instance, never per recommendation request. New scaled instances initialize separately.
- Test catalog search/pagination, a unique selection, and the real pair `60-652-95R` + `DH-IPC-HDBW4431R-ZS` → `DS-2CD2142FWD-I`. Add `0806-001` to clear recommendations; remove it to restore them; clear and refresh.
- Confirm browser network requests stay on the preview's HTTPS domain. Initial server catalog requests must reach that preview's backend through the binding. Test a protected preview too; internal binding calls do not go through public Deployment Protection.
- Exercise loading and retry on a cold instance. The UI has a five-second request timeout; if a measured cold start exceeds that, document and fix the experience before promotion. A 60-second backend maxDuration does not override the shorter browser timeout.
- Measure actual Linux function bundle size, peak memory, cold/warm latency, and logs. The standard Python limit currently documented is 500 MB uncompressed; Hobby memory is 2 GB. The local macOS development environment's size is **not** proof of a Linux bundle's size. Do not enable paid capacity or large-function beta as an automatic workaround.
- Capture the hosted manual journey as a real MP4 and verify playback. The existing local acceptance videos prove local behavior only.

## Rollback and fallback

Use Vercel's deployment rollback to restore the previously accepted **whole deployment**, so frontend, backend, CSV, and bundled code return together. Record and retain the matching environment values; a dashboard variable change is not a source-controlled code change, and its restoration must be checked explicitly. Recheck readiness/modelVersion and the real pair after rollback.

If Services beta is unavailable or its hosted checks fail, stop promotion and keep the working local app. The fallback is two Vercel projects connected to this **same repository**. That requires a separate reviewed configuration: backend root `.`, frontend root `client/`, explicit frontend-to-backend origins/CORS, and coordinated version promotion/rollback. No repository split or rewrite of Apriori into JavaScript is needed.

## Verification performed for this PR

- 48 backend tests passed, including importing a copied deployment bundle from an unrelated directory and proving canonical data, the real rule, and one mining call across repeated requests.
- Three frontend API tests passed: same-origin catalog query, recommendation request body/URL, and preservation of a binding URL's path prefix. Lint and TypeScript checks passed.
- Same-origin production build passed using `next build --webpack`, with no server binding available at build time. Turbopack in this isolated worktree could not follow the temporary shared `node_modules` symlink outside its root; CI uses normal installs and the standard Turbopack build.
- Configuration matched the current published Vercel JSON schema using Ajv. Schema meta-validation was disabled because Vercel's schema declares draft-04 but includes newer numeric `exclusiveMinimum` syntax; configuration validation itself was enabled.
- No Vercel project was linked, no hosted build/deployment was invoked, and no hosted latency, billing, or uptime claim is made.
